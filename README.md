# LLM-Internals and deep-dive   

A standard layout for llm-internals and deep-di on training, transformer internals and inference engineering.


```text
inference-deep-dive/
├── README.md                      # table of contents linking every topic file
├── docs/                          # tutorial-style deep dives, one file per topic
│   ├── self-attention.md
│   ├── feed-forward-network.md
│   └── foundations/               # pure math, independent of any code or architecture
│       ├── softmax.md             # standalone, 3–4 pages
│       ├── gradient.md            # chain rule, gradient descent
│       ├── activation-functions.md
│       ├── sgd.md
│       └── adam.md
├── diagrams/
│   ├── make_diagrams.py           # scripts that generate every figure
│   └── *.png / *.svg              # exported outputs
├── code/
│   ├── attention/
│   │   └── attention.py           # spans training and inference
│   ├── inference/
│   │   └── kv_cache.py            # decode-only, inference-specific
│   └── requirements.txt
├── notebooks/                     # interactive exploration
├── benchmarks/                    # throughput, latency tables, configs
└── tools/                         # one subfolder per tool, each with its own README
    ├── megatron/
    │   └── README.md
    ├── triton/
    │   └── README.md
    └── vllm/
        └── README.md
```

`foundations/` sits inside `docs/`, so the pure-math files (softmax, gradient, activation functions, SGD, Adam) still live with the other docs, but read as their own layer underneath the architecture tutorials.

## What goes where

| Path | Contents |
|---|---|
| `README.md` | The table of contents. It links to every topic file, with one line on what each covers and a suggested reading order. |
| `docs/` | Tutorial-style deep dives, one file per topic, such as `self-attention.md` and `feed-forward-network.md`. |
| `docs/foundations/` | Pure-math topics: softmax, gradient (chain rule and gradient descent), activation functions, SGD and Adam. None of them depend on code or on any one architecture. |
| `diagrams/` | Diagram scripts (matplotlib or Excalidraw) plus the exported PNG and SVG files. Matrix diagrams, such as Q, K and V blocks that grow a row at a time, are generated by code so they can be rerun. Mermaid is only for flowcharts and sequence diagrams. |
| `code/attention/` | `attention.py`. Attention is used in both training and inference. |
| `code/inference/` | `kv_cache.py`. It only applies to decode, which happens only at inference. |
| `notebooks/` | Jupyter notebooks for interactive exploration. |
| `benchmarks/` | Throughput numbers, latency tables, and the configs used in each experiment. |
| `tools/<tool>/` | One folder per tool (Megatron, Triton, vLLM), each with a README holding install notes, quirks you ran into, and benchmark results. |

## Rules

1. **Markdown, not PDF.** It can be version-controlled and diffed, and GitHub renders it.
2. **Diagrams come from scripts.** Never hand-edit an exported image. Change the script and rerun it.
3. **Keep prose separate from code.** Someone who clones the repo should be able to run `code/` without reading the docs.
4. **One topic per file.** Split a long document (40 to 50 pages) into topic files, and let `README.md` be the table of contents.
5. **Pure-math topics are their own docs.** Softmax, gradient, activation functions, SGD and Adam each get a file in `docs/foundations/`, not a section buried inside an architecture tutorial.
6. **Link, don't copy.** `softmax.md` is written once and linked from the attention, loss and sampling docs. The same goes for every foundations topic.
7. **Tools sit beside docs and code.** Keeping `tools/` at the top level keeps the math and architecture material clean, while every tool still has a home.
8. **GitHub is the source of truth.** Medium cross-posts (@analog76) link back to the repo.

## Why kv_cache.py lives under inference/

Training does not use a KV cache. In training the whole sequence is known in advance, so the full attention matrix is built in one pass, with a causal mask that stops each token from seeing later ones. The KV cache exists only for inference, where tokens are generated one at a time. There it stores the K and V rows of earlier tokens so they don't have to be recomputed at every step.

So `attention.py` sits in `code/attention/`, because both phases use it, and `kv_cache.py` sits in `code/inference/`, because only decoding needs it.

## Reproduce

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r code/requirements.txt
python diagrams/make_diagrams.py        # regenerates every figure
python code/attention/attention.py
python code/inference/kv_cache.py
```
